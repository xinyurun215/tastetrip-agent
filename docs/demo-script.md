# TasteTrip 两分钟演示

从「两个人的口味冲突」走到「撕开的票根被订成一张行程」。按这个顺序点，页面和动画就是这个顺序。全程大约 2 分钟。预览地址写在 README 的 Preview 一节。

口味是固定这一对：小众爵士 × 夜宵。旅人 A Whiplash / 小众爵士 Kamasi Washington / Blue Note，旅人 B 深夜食堂 / 深夜食堂 / 夜宵。没有服务器密钥时，行程是规则基线，来源标记 mock:fixture，并写明这次是备用数据。票根上是文字，不是海报。

## 0:00 一句话

打开页面，停在纸色第一屏。读标题：

> 两个人的口味冲突 → 找出重叠

不要先讲功能清单。这句话就是产品。

## 0:20 一键试玩

点墨色按钮 **一键试玩**。页面滚到 Agent 四步。四格一开始都是「等待」。

## 0:30 解析口味

第一格 **解析口味** 标成完成，中间结果是两边的六个词：

> A Whiplash / 小众爵士 Kamasi Washington / Blue Note · B 深夜食堂 / 深夜食堂 / 夜宵

## 0:50 询问 Qloo

第二格 **询问 Qloo** 完成。没有服务器密钥时，结果写着 **规则基线 · mock:fixture**。浏览器只把口味文字 POST 到 `/api/qloo`。密钥只在服务器上。有密钥时，代理用 GET 打 `https://hackathon.api.qloo.com` 的 `/search` 和 `/v2/insights`，标记变成 `qloo:entity`。

## 1:10 标出冲突

第三格 **标出冲突** 完成，下面两张票根滑进来。

- 左边实线票根是旅人 A，右边虚线票根是旅人 B。同一支墨色，不是两种颜色。
- 中间裂口是 **冲突**。
- 没有密钥时是两处，标记 `mock:fixture`：城市气质 / City vibe，用餐方式 / Dining style。有密钥时，标题换成 Qloo 返回的实体名，并带上响应里的亲和度，标记 `qloo:entity`。

指着裂口说：不是把两个人平均成一个无聊的中间点，而是先承认这两处对不上。

## 1:25 重排

第四格 **重排路线** 完成后，朱红行程线从裂口下面展开。实线和虚线还在左右，表示两张票被订回一张。

没有密钥时，交集是 **都会夜生活 / Urban nightlife**，标记 `mock:fixture`。四站都有标签 **为什么两人都喜欢 · Why both will like it**：

1. 19:30 爵士窄门
2. 20:10 夜宵窗口
3. 21:40 只留一首
4. 23:15 热食收口

有密钥时，这四站换成纽约城里的餐饮或现场音乐场地，每站并排 A、B 两个真实亲和度，标记 `qloo:entity`。缓存命中写着 Qloo 实时结果（已缓存）。失败写着这次是备用数据。

## 1:50 收束

指着行程底部的来源标记。没有密钥时是 `mock:fixture`。限流、超时或宕机会留下一枚朱红小签，票根和规则基线还在，页面不会空白。

如果还剩十几秒，点 **对照页**。没有密钥时左栏说明这次没有 Qloo 响应，不把规则基线写成图谱。右栏是不读图谱的规则，标记 `mock:fixture`。有密钥时左栏才是 live 实体和 `qloo:entity`。不要说谁赢了。

到这里大约 2 分钟。如果要再看一遍动画，滚回顶部再点一次 **一键试玩**。
