# TasteTrip 两分钟演示

从「两个人的口味冲突」走到「撕开的票根被订成一张行程」。按这个顺序点，页面和动画就是这个顺序。全程大约 2 分钟。预览地址写在 README 的 Preview 一节。

口味是固定假数据：旅人 A《布达佩斯大饭店》/ 爵士 / 火锅，旅人 B Marvel / 嘻哈 / 寿司。海报位是标了 placeholder 的色块，不是照片。

## 0:00 一句话

打开页面，停在黑底第一屏。读标题：

> 两个人的口味冲突 → 找出重叠

不要先讲功能清单。这句话就是产品。

## 0:20 一键试玩

点黄色按钮 **一键试玩**。页面滚到 Agent 四步。四格一开始都是「等待」。

## 0:30 解析口味

第一格 **解析口味** 变黄，中间结果是两边的六个词：

> A 《布达佩斯大饭店》 / 爵士 Jazz / 火锅 · B Marvel / 嘻哈 Hip-hop / 寿司

## 0:50 询问 Qloo

第二格 **询问 Qloo** 完成。现在没有服务器密钥，所以结果写着 **回退**，实体 id 是 `mock:` 加原词，不是 Qloo 返回的。浏览器只把口味文字 POST 到 `/api/qloo`。密钥只在服务器上。没有密钥时代理不打 Qloo。

## 1:10 标出冲突

第三格 **标出冲突** 完成，下面两张票根滑进来。

- 左边橙色票根是旅人 A，右边蓝色是旅人 B。
- 中间裂口是 **冲突**。
- 两处：城市气质 / City vibe，用餐方式 / Dining style。

指着裂口说：不是把两个人平均成一个无聊的中间点，而是先承认这两处对不上。

## 1:25 重排

第四格 **重排路线** 完成后，黄色行程从裂口下面展开。左右还留着橙色和蓝色的边，表示两张票被订回一张。

交集是 **都会夜生活 / Urban nightlife**。四站都有黑底标签 **为什么两人都喜欢 · Why both will like it**：

1. 19:30 对称旅馆大堂
2. 20:10 双柜台夜食堂
3. 21:40 爵士转角 → 嘻哈地下室
4. 23:15 天台双银幕

读第 2 站和第 4 站的理由。第 2 站是火锅和寿司并桌。第 4 站是两块银幕都留在夜里。

## 1:50 收束

指着行程底部：理由仍是假的。服务器配上密钥之后，第二步才会打 `https://hackathon.api.qloo.com` 的 search 和 insights。限流、超时或宕机会留下橙色 Fallback 条，票根和夜路还在，页面不会空白。

如果还剩十几秒，点 **对照页**。同一对口味左右并排。两边都标着 placeholder。不要念任何分数，因为还没有测量。

到这里大约 2 分钟。如果要再看一遍动画，滚回顶部再点一次 **一键试玩**。
