# 阶段 2：Qloo 多成员 harness（测试线束）

阶段 2 通过服务端显式模式 `mode: "members-harness"` 运行，不把多成员输入送进旧的 A/B 评分或路线模块。

## 输入与位置

- 输入沿用 `members[]` 和全局 `context`；共同路线统一使用全局目的地，成员城市和起点不覆盖查询范围。
- 文本目的地通过现有 Qloo `/search` 的 `urn:entity:locality` 类型查询；仅接受唯一名称/别名精确匹配且有有效坐标的结果。同名地点可补充响应支持的国家代码或地区。无法确认时返回 `destination_*` 和空路线，不进行全球候选搜索。
- 匹配项还必须具有唯一明确的 `urn:tag:genre:locality:city` 类型；省、州、岛和街区不能代替城市，缺少类型的精确同名项仍作为潜在歧义保留。
- 已解析目的地使用 locality ID 和 `filter.location.radius=0` 查询，不放宽行政边界；候选还必须有有效坐标并位于中心 12 公里内。API 显式坐标输入沿用点/半径查询，表示坐标范围，不等同于已验证城市边界。
- 城市、国家、坐标和地址仅来自候选响应；缺失城市保留为空，不用输入覆盖。地理证据不足或范围外候选不会进入公平评分和路线，无合格候选返回 `no_verified_places`。
- 旧双人 Demo 在 fixture 中显式提供纽约坐标，浏览器代理会转发 `context`。

## 可复核输出

`resolveMembersHarness` 返回每位成员的 Qloo 实体和地点候选，并保留：

- `requestLog`：请求 URL、类型、实体、标签、成员、城市、坐标、尝试次数、来源和结果摘要；
- `requestStats`：总请求、网络请求、重试、限流、失败和缓存命中；
- `quota`：已用请求数、可选配额上限和剩余量。

Qloo 实体和候选地点标记 `qloo:entity`。没有密钥、限流、超时或不可达时，结果明确标记 `fallback` / `mock:fixture`，并保留已发生请求的审计信息。

## 验证

测试覆盖 N=3、动态上海坐标、成员顺序串行、429 有界重试、HTTP 缓存、配额统计、缺少密钥和失败回退。阶段 2 不包含公平评分、路线优化、动态界面或协商 Agent。
